# EcoRoute — система мониторинга отходов

EcoRoute — веб-приложение для мониторинга заполненности контейнеров и планирования их вывоза. Панель показывает контейнеры на карте, текущие показатели и состояние датчиков; маршрут строится от местоположения пользователя через критические точки.

Интерфейс поддерживает украинский и английский языки. В демонстрационном наборе используются 10 контейнеров в Одессе.

## Возможности

- карта контейнеров с поиском и фильтром по статусу;
- сводка по общему количеству, заполненным и почти заполненным контейнерам, а также среднему уровню заполнения;
- обновление данных панели каждые 15 секунд;
- планирование маршрута к контейнерам со статусом «полный» по геолокации пользователя;
- регистрация и вход с подтверждением электронной почты, восстановление пароля;
- приём показаний датчиков, хранение истории измерений и оповещения в Discord;
- симулятор датчиков для демонстрации работы системы.

## Технологии

- **Клиент:** React 18, TypeScript, Vite, Leaflet / React Leaflet
- **Сервер:** Node.js 22, Express, TypeScript
- **База данных:** PostgreSQL 16
- **Развёртывание:** Docker Compose; опционально ngrok для публичного туннеля

## Быстрый запуск через Docker

Требуются Docker Engine или Docker Desktop с Compose. Создайте в корне файл `.env` и задайте как минимум два значения:

```dotenv
POSTGRES_PASSWORD=замените_на_надёжный_пароль
COMPOSE_DATABASE_URL=postgres://eco:замените_на_надёжный_пароль@db:5432/ecoroute
```

Пароль в `COMPOSE_DATABASE_URL` должен совпадать с `POSTGRES_PASSWORD`. Запустите сервисы:

```bash
docker compose up --build
```

Откройте <http://localhost:4000>. API доступен по тому же адресу, проверка состояния — <http://localhost:4000/api/health>. Compose поднимает PostgreSQL, API и симулятор показаний. Ngrok запускается как дополнительный сервис; для публичного туннеля укажите `NGROK_AUTHTOKEN`.

Для остановки нажмите `Ctrl+C`, затем выполните `docker compose down`. Данные PostgreSQL сохраняются в Docker volume `postgres_data`; чтобы удалить базу вместе с данными, используйте `docker compose down -v`.

## Локальная разработка

Требуются Node.js 22+, npm и доступный PostgreSQL 16. Создайте базу `ecoroute`, примените `database/init.sql`, установите зависимости и настройте окружение:

```bash
npm ci
```

Создайте `.env` со строкой подключения к локальной базе и нужными параметрами, например:

```dotenv
DATABASE_URL=postgres://eco:пароль@localhost:5432/ecoroute
PORT=4000
ALERT_THRESHOLD=85
```

Запустите клиент и API в режиме разработки:

```bash
npm run dev
```

Vite доступен по адресу <http://localhost:5173>, API — на порту `4000`. Для работы с учётными записями настройте SMTP (см. переменные окружения ниже). Запустить симулятор отдельно можно командой `npm run simulate`; по умолчанию он отправляет показания на `http://localhost:4000` каждые 15 секунд.

## Переменные окружения

| Переменная | Назначение | Значение по умолчанию / требование |
|---|---|---|
| `DATABASE_URL` | Подключение к PostgreSQL для локального запуска | Обязательна для API вне Compose |
| `COMPOSE_DATABASE_URL` | Подключение API к БД в Compose | Обязательна при запуске Compose; хост обычно `db` |
| `POSTGRES_PASSWORD` | Пароль пользователя PostgreSQL в Compose | Обязательна |
| `PORT` | Порт API | `4000` |
| `ALERT_THRESHOLD` | Порог статуса «полный» и отправки алерта, в процентах | `85` |
| `SENSOR_API_KEY` | Bearer-токен для отправки показаний датчиков | Не задан; если задан, отправителю нужно передавать его в `Authorization: Bearer <ключ>` |
| `SIMULATOR_INTERVAL_MS` | Интервал симулятора | `15000` |
| `API_URL` | Адрес API для симулятора | `http://localhost:4000`; в Compose — `http://api:4000` |
| `DISCORD_WEBHOOK_URL` | Discord webhook для уведомлений о заполненных контейнерах | Не задан |
| `SMTP_HOST`, `SMTP_PORT`, `SMTP_SECURE` | SMTP-сервер и параметры TLS | Порт `587`, `SMTP_SECURE=false` |
| `SMTP_USER`, `SMTP_PASS` | Учётные данные SMTP | Нужны для регистрации и восстановления пароля |
| `MAIL_FROM` | Адрес отправителя писем | Нужен для регистрации и восстановления пароля |
| `APP_BASE_URL` | Публичный базовый адрес приложения для ссылок в письмах | В Compose по умолчанию `http://localhost:4000` |
| `CORS_ORIGINS` | Разрешённые браузерные источники, через запятую | `http://localhost:5173,http://127.0.0.1:5173` |
| `NGROK_AUTHTOKEN` | Токен ngrok для публичного туннеля | Не задан |

Регистрация доступна только при настроенной доставке почты. Пароль аккаунта должен содержать от 12 до 128 символов. Геолокация браузера работает на `localhost` или по HTTPS.

Не добавляйте реальные пароли, SMTP-учётные данные и токены в репозиторий. Используйте локальный `.env` и храните его вне системы контроля версий.

## API

Для защищённых маршрутов требуется активная сессия. Единственное исключение — `POST /api/measurements`, если настроен `SENSOR_API_KEY`: его можно вызывать с Bearer-токеном датчика.

| Метод | Путь | Назначение |
|---|---|---|
| `GET` | `/api/health` | Проверка доступности API и подключения к базе |
| `POST` | `/api/auth/register` | Регистрация и отправка письма подтверждения |
| `GET` | `/api/auth/verify?token=...` | Подтверждение электронной почты |
| `POST` | `/api/auth/login` | Вход |
| `POST` | `/api/auth/logout` | Выход |
| `GET` | `/api/auth/me` | Текущий пользователь |
| `POST` | `/api/auth/forgot-password` | Запрос ссылки для сброса пароля |
| `POST` | `/api/auth/reset-password` | Установка нового пароля по токену |
| `GET` | `/api/containers` | Список контейнеров и последние известные показатели |
| `GET` | `/api/stats` | Сводная статистика |
| `GET` | `/api/measurements?containerId=CNT-001` | Последние показания, опционально для одного контейнера |
| `POST` | `/api/measurements` | Приём измерения датчика |

Пример тела запроса для отправки показания:

```json
{
  "containerId": "CNT-001",
  "fillPercent": 86,
  "weightKg": 103.2
}
```

`fillPercent` должен быть числом от 0 до 100, `weightKg` — неотрицательным числом. Статус `full` назначается при достижении `ALERT_THRESHOLD`, `warning` — начиная с 70%.

## Команды проекта

| Команда | Действие |
|---|---|
| `npm run dev` | Запуск API и Vite для разработки |
| `npm run dev:api` | Запуск API с перезапуском при изменениях |
| `npm run dev:web` | Запуск Vite |
| `npm run build` | Сборка TypeScript API и клиентского приложения |
| `npm start` | Запуск собранного сервера и клиентских файлов |
| `npm run simulate` | Запуск симулятора датчиков |
| `npm run typecheck` | Проверка типов клиента и сервера |

```text
web/src/    React-интерфейс, карта и локализация
```

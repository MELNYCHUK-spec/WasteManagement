# EcoRoute

Прототип IoT-системы мониторинга заполненности контейнеров и планирования сбора отходов. Стек: React + TypeScript, Node.js + Express, PostgreSQL и Docker Compose.

Інтерфейс доступний українською та англійською мовами. Перемикач UA / EN розташований у верхній панелі; вибір зберігається у браузері.

## Быстрый запуск

1. Скопируйте `.env.example` в `.env` и при необходимости добавьте URL Discord webhook.
2. Запустите `docker compose up --build`.
3. Откройте `http://localhost:4000`.

### Публичная ссылка через ngrok

Добавьте `NGROK_AUTHTOKEN` из панели ngrok в локальный `.env`, затем запустите `docker compose up --build -d`. Ссылка появится в выводе `docker compose logs -f ngrok`. Остановка туннеля: `docker compose stop ngrok`. Туннель открывает интерфейс и API приложения на порту 4000.

PostgreSQL автоматически создаёт таблицы и демонстрационные контейнеры при первом запуске. Имитатор датчиков каждые 15 секунд отправляет показания в REST API. Данные сохраняются в именованном томе `postgres_data`.

Для локальной разработки запустите PostgreSQL через `docker compose up db`, затем выполните `npm install` и `npm run dev`. Vite откроет интерфейс на `http://localhost:5173`, Express API работает на `http://localhost:4000`. Имитатор запускается отдельно командой `npm run simulate`.

## Discord уведомления

Создайте Incoming Webhook в настройках Discord канала и задайте его адрес в `.env`:

```env
DISCORD_WEBHOOK_URL=https://discord.com/api/webhooks/...
ALERT_THRESHOLD=85
```

Уведомление отправляется один раз при переходе контейнера в статус «Заполнен» (по умолчанию от 85%). Когда контейнер опустится ниже порога, следующий переход снова создаст уведомление. URL хранится только в переменных окружения API.

## REST API

| Метод | Путь | Назначение |
| --- | --- | --- |
| GET | `/api/health` | Проверка API и подключения к БД |
| GET | `/api/containers` | Список контейнеров и текущие статусы |
| GET | `/api/stats` | Сводные показатели панели |
| GET | `/api/measurements?containerId=CNT-001` | Последние показания датчиков |
| GET | `/api/routes` | Сохранённые маршруты |
| POST | `/api/measurements` | Приём показания датчика |

Пример тела `POST /api/measurements`:

```json
{ "containerId": "CNT-001", "weightKg": 86.4, "fillPercent": 72 }
```

Статусы: `normal` (менее 70%), `warning` (70% до порога), `full` (от порога заполнения). Карта использует Leaflet и тайлы OpenStreetMap; демо-точки для разработки расположены в районах Хургады. Замените их координаты на фактические координаты датчиков перед рабочим использованием.

После нажатия «Построить маршрут» приложение берёт геопозицию браузера и включает только контейнеры со статусом `full` в радиусе 75 км. Контейнеры `warning` и `normal` пропускаются. Критические точки сортируются по убыванию заполненности; при одинаковом уровне выше ставится ближайший контейнер. Затем OSRM строит путь по дорожной сети в этом приоритетном порядке и рассчитывает время; маршрут можно открыть в Google Maps. Геолокация требует разрешения браузера и HTTPS (для локальной разработки подходит `http://localhost`). Для рабочей эксплуатации используйте реальные координаты контейнеров и собственный или согласованный routing-сервис вместо публичного демо-сервера OSRM.

## Структура

- `web/src/features` — изолированные функции интерфейса, включая Leaflet-карту.
- `web/src/types` — типы данных интерфейса.
- `server/app.ts` — настройка Express и подключение маршрутов API.
- `server/routes` — отдельные маршруты health, контейнеров, статистики, показаний и маршрутов.
- `server/db/pool.ts` — пул подключений PostgreSQL.
- `server/config.ts` — настройки API из переменных окружения.
- `simulator` — генератор показаний датчиков.
- `database/init.sql` — схема PostgreSQL и стартовые данные.
- `database/migrations` — SQL-обновления для уже созданной базы.
- `docker-compose.yml` — база, API и симулятор.
